# CR-K8S-002: Kubernetes Secret Ingestion via Environment Variables

| Attribute | Details |
|---|---|
| **Rule ID** | `CR-K8S-002` |
| **Category** | Security |
| **Severity** | Medium |
| **Confidence** | High |
| **CWE** | [CWE-526: Cleartext Storage of Sensitive Information in an Environment Variable](https://cwe.mitre.org/data/definitions/526.html) |
| **OWASP Top 10** | A05:2021 - Security Misconfiguration |

---

## Description
Exposing secrets (API keys, database credentials, TLS certificates) to container processes through environment variables (`secretKeyRef` or `secretRef`) is an anti-pattern. Environment variables leak easily into:
- Unprivileged child subprocesses
- Application stack traces and crash dumps
- `/proc/[pid]/environ` pseudo-filesystem
- Observability and APM agent metadata logs
- Output from `kubectl describe pod` and container engine inspect commands

---

## Non-Compliant Code Example
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: api-service
spec:
  containers:
    - name: api
      image: codexa/api:latest
      env:
        - name: DB_PASSWORD
          valueFrom:
            secretKeyRef:
              name: db-credentials
              key: password
```

---

## Compliant Solution
Mount the secret as a read-only filesystem volume with restricted file permissions (`defaultMode: 0400`):

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: api-service
spec:
  containers:
    - name: api
      image: codexa/api:latest
      volumeMounts:
        - name: db-secret-volume
          mountPath: /etc/secrets/db
          readOnly: true
  volumes:
    - name: db-secret-volume
      secret:
        secretName: db-credentials
        defaultMode: 256 # 0400 octal
```

---

## Alternative: Secrets Store CSI Driver & External Secrets (ESO)
In modern cloud-native Kubernetes clusters (EKS, GKE, AKS), use the **Secrets Store CSI Driver** with AWS Secrets Manager, Azure Key Vault, or HashiCorp Vault. Sensitive credentials are mounted into the pod memory ephemeral filesystem without ever persisting plain Kubernetes Secret manifests in etcd:

```yaml
apiVersion: secrets-store.csi.x-k8s.io/v1
kind: SecretProviderClass
metadata:
  name: aws-secrets-provider
spec:
  provider: aws
  parameters:
    objects: |
      - objectName: "production/db/credentials"
        objectType: "secretsmanager"
```
