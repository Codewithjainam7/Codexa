# CR-K8S-001: Kubernetes HostPath Mount & Insecure SecurityContext

| Metadata | Specification |
| :--- | :--- |
| **Rule ID** | `CR-K8S-001` |
| **Severity** | `CRITICAL` |
| **Category** | `SECURITY` |
| **CWE ID** | [CWE-284: Improper Access Control](https://cwe.mitre.org/data/definitions/284.html) |
| **OWASP Top 10** | A05:2021 – Security Misconfiguration |
| **Languages** | Kubernetes YAML, Helm |

---

## Vulnerability Overview

Using `hostPath` volumes in Kubernetes mounts underlying worker node host filesystem directories into the container. Attackers who achieve container code execution can read or write host configuration files (`/etc/shadow`, `/var/run/docker.sock`, `/proc`), leading to instantaneous node breakout and cluster administrative escalation.

---

## Secure Remediation

Use `persistentVolumeClaim` or ephemeral storage (`emptyDir`), and restrict pod security standards using admission controllers (PodSecurity admission level `restricted`):

```yaml
volumes:
  - name: secure-volume
    persistentVolumeClaim:
      claimName: app-pvc
```
